## 依据、范围与阅读方式

已读取原始《宠物小窝 Web 应用项目开发文档 V3.0》（根目录 Word），重点对应 4、5.1–5.6、6、7、8.5、10、11.2、12.2 节；同时核对用户后续确认的 +86 注册/双向绑定、AI 即时回答、P1、词库审核及 [P1 指南](P1.md)、[数据库](DATABASE.md)、[接口](API.md)、[审核操作说明](MODERATION.md)。用户后续决定优先于原始选型示例。

- P0、已实现 P1 及其权限、安全、异常、界面和交付纳入本表；P2 不开发、不算测试失败。
- Supabase Auth 管理身份和密码，UUID、RLS、RPC、对象路径取代原文的 bigint、自建密码接口及图片 URL 示例。
- 宠物档案继续私有，社区只分享主动选择的宠物名称；不因原文的可选公开档案而放宽健康资料权限。
- 仅词库审核；图片做文件/归属检查，没有 OCR 或画面识别。人工评论下架是永久删除，不能按软删除验收。
- 每行是一项验收场景，**不等于一个 Vitest 测试**。多行可共享同一组测试证据，不重复累计为新的自动测试数量。
- “通过”只限证据标注的层次；“待实测”不能算通过；“缺口”表示与需求相比尚未满足。真实设备、真实收件、生产观察分别验收。

前置条件简称：**L**＝依赖已安装、本地测试环境；**C**＝明确的 Supabase 开发项目，临时测试账号/数据；**U**＝本机前端连接真实开发后端、已有专用测试账号 A；**M**＝用户实际拥有的邮箱/手机号或手机设备。

证据简称：**DB**＝`tests/database.test.ts`（真实迁移 + PGlite 平台夹具）；**AI**＝`tests/ai.test.ts`（HTTP/仓储注入，无真实上游）；**C01–C26**＝`test-results/full-cloud.json` 的本轮真实云端分组；**U01–U…**＝`test-results/full-browser.json` 的本轮页面操作；**PERF**＝`test-results/full-performance.json`。这些原始报告被 Git 忽略，结论保存在 [本轮测试报告](FULL-TEST-REPORT.md)。
