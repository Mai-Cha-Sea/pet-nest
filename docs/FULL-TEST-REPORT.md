## 真实云端业务与并发

`scripts/full-cloud.mjs` 只接受已明确的开发域名，需显式启用及进程内管理员凭据。它不使用用户 Test_01、原 A/B 的数据做并发压力或重置额度；创建的 3 个随机临时 Auth 用户只用于本轮。

- 真实登录、资料触发器、修改/刷新、错误密码、匿名访问；修改空昵称/超长简介和跨用户写入均被拒绝。
- 创建完整档案、编辑、非法字段、伪造归属与 B 对 A 的读/改/删拒绝。12 个实际并发创建恰好 10 成功、2 个 PET_LIMIT；删除一只后可再次创建。
- 六类记录写入正确宠物；59 条记录按时间取 50+9 页、无重复，新客户端仍能读取。异常 9 图接受，10 图拒绝；SVG、超过 5MiB、越权对象路径拒绝。
- 25 个实际并发服务端额度预留恰好 20 成功、5 个 DAILY_LIMIT；Edge 下一次为 429。该并发测试上游请求为 0，不制造 25 次模型费用。
- 真正的 DeepSeek 回答引用所选猫的 42g/4.1kg，不引用另一用户的 8.2 或隔离狗粮；保存一问一答、model、token 和耗时。同 ID 复用不加计次，更换内容为 409。急症即时线下指引，token=0。
- 社区开通、草稿隔离、宠物名称快照、三标签、8 个同时点赞只计一次、私有收藏、关注流/粉丝、评论重试/一级回复/举报私有、真实图片自动发布和管理员下架均通过。
- 管理员按 comment_id 复核并将举报置为 dismissed 时保留正文；按 ID+正文删除临时父评论时连带回复和举报被清理，与新审核操作说明一致。

上游 429/503/超时/无效 JSON、提交响应丢失、保存失败和历史延迟，是本轮重新运行的受控传输/组件测试，**不是**故意损坏云端配置或真实服务故障演练。系统提示与词库也不能证明覆盖所有风险输入。

## 重跑方法

本地完整检查和格式检查照 [TESTING.md](TESTING.md)。新增云端脚本使用进程内 `TEST_ADMIN_KEY`，不要放到 `VITE_` 变量或提交仓库；已有配置不覆盖：

```powershell
# 已按 TESTING.md 准备 .env.test.local；仅对指定开发项目执行。
# TEST_ADMIN_KEY 由本机已授权的管理工具注入进程，命令/日志中不填写真实值。
$env:TEST_ALLOW_FULL_TESTS='yes'
$env:TEST_ENABLE_AI='yes'  # 至多一次真实模型调用；并发额度测试不调用模型。
node scripts/full-cloud.mjs

# 只读采样，使用现有专用 A 登录，不修改业务数据。
node scripts/measure-cloud.mjs
```

完整云端脚本失败会非零退出并保留分步报告；先检查失败点和 cleanupErrors，再决定重跑。只有确定清理完成才能把执行结论标为完整。UI 检查按测试表步骤在正常浏览器执行，不能用注入 API 成功响应代替。
