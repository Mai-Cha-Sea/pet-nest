# 宠物小窝测试与验收指南

适用版本：0.2.0（P1）。编写日期：2026-10-29。本册面向测试人员、验收人和维护开发者，给出执行顺序、数据准备、关键场景、证据与交付判定，并附项目现有 101 项场景表。历史结果均保留来源和边界，本次整理 Word 不代表又执行了一轮业务联调。

## 先确定测试范围

P0 覆盖用户、宠物档案、六类记录、AI 与基础页面；P1 覆盖体重曲线、图文/标签、互动、关注、举报和词库审核。P2 搜索、百科、交易、视频、在线问诊和寄养预约不在范围内。私有档案不因社区功能而放宽权限。

| 验证层                    | 能说明什么                                | 不能替代什么                   |
| ------------------------- | ----------------------------------------- | ------------------------------ |
| 类型 格式和构建           | 代码可编译、规则和构建配置可执行          | 真实用户收件或云端权限         |
| 纯函数与组件测试          | 校验、状态转换、mock 边界下的真实页面交互 | 实际短信、模型故障和真实设备   |
| PGlite 执行真实 SQL       | 迁移语法、关系、RLS/RPC 和约束的已测行为  | 完整 Supabase 平台和多连接压测 |
| 开发云端 REST RPC Storage | 真实服务的身份、持久化、隔离及受控并发    | 任意规模性能和全部异常穷尽     |
| 浏览器与人工实测          | 页面读写、布局、真实收件和设备行为        | 没有实际持续观察的生产稳定性   |

每条结论写清日期、代码提交、环境和证据。SKIPPED 不计通过，用户反馈与代理自动执行分开记录；已有截图不证明今天又做了同一步操作。

## 环境和测试数据

使用专用开发项目及 A/B 两个账号。既有 A/B 的本机账号文件不在公开仓库，新维护者应通过安全渠道获得或自行创建；不把测试密码放进 Word。手机号实测只用本人中国大陆号码，邮箱需能完成真实确认，不能向虚构或他人号码发送验证码。

A 与 B 使用不同浏览器或无痕环境，防止普通标签页共享会话。记录测试前宠物、动态、关注、额度和对象基线；临时对象加明确测试标识。需要清理时只处理本轮明确创建的数据，不重置既有账号密码、号码、日额度或原有资料。

本地检查不需要生产密钥。服务端管理测试凭据仅在被忽略文件或短期进程中提供，不加 VITE_ 前缀。当前项目没有 Docker，SQL 平台对象是 PGlite 夹具；若另行使用完整本地 Supabase，先按官方与项目部署说明配置独立环境。

## 执行本地自动检查

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run format:check
npm.cmd run test:preview
```

check 包含前端及三个 Edge 类型检查、Vitest、构建及前端产物扫描。当前 14 个测试文件共 150 项；以每次真实输出为准。preview 临时启动并关闭项目预览，检查九个入口及主 JS，不替代真实云端业务。

| 修改领域             | 优先核对的现有测试                                  |
| -------------------- | --------------------------------------------------- |
| 字段 记录 日期 图片  | domain、api、views、database                        |
| 注册 同意 账号绑定   | account、auth-view、bindings-view、router、database |
| AI 上下文 编排和界面 | ai、api、views、database                            |
| 社区 标签 评论和统计 | community、community-views、legal-profile、database |
| 体重图               | growth、api                                         |
| 短信签名与事件去重   | sms；真实投递另测                                   |

失败时保留首个失败原因，修复后重跑受影响检查；不能删断言、注释测试或返回假响应让结果通过。注释补充曾核对 84 个源码文件、六份迁移未变及 31 个构建文件摘要相同，该项属于静态和产物一致性证据。

## 真实云端脚本的区别

| 脚本                 | 开关和数据影响                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| live-smoke.mjs       | TEST_ALLOW_WRITES=yes；使用 A/B 创建并清理临时宠物、记录和图片，真实 AI 另由 TEST_ENABLE_AI 开启 |
| cloud-acceptance.mjs | 还需管理 key、写入和管理开关；保留演示/QA 数据，与临时账号清理脚本不同                           |
| p1-cloud.mjs         | TEST_ALLOW_P1_TESTS=yes 和管理 key；社区临时对象清理，原有关注/昵称不覆盖                        |
| full-cloud.mjs       | TEST_ALLOW_FULL_TESTS=yes 和管理 key；创建临时账号，执行 26 组业务并清理；真实模型另设开关       |
| gap-cloud.mjs        | TEST_ALLOW_GAP_TESTS=yes 和管理 key；协议声明与获赞专项，清理临时账号，不发模型/短信/邮件        |
| measure-cloud.mjs    | 小量只读计时与站点状态采样，不是压测或真实 4G 首屏测量                                           |

先阅读具体脚本和 docs/TESTING.md，再在已确认的开发环境启用。不要在 CI 默认执行云端写入，也不为测试故意损坏现有模型或短信配置。清理失败应记为待处理或失败，不能仅因业务断言通过就宣称全轮完成。

## 人工业务闭环

依次执行下列流程，保留可核对的截图、对象 ID 或去敏报告。截图不得包含密码、验证码、管理 key 或真实私密资料。

1. 新账号通过邮箱或手机号注册，阅读协议并主动同意，真实完成对应验证后登录。
2. 修改私人昵称和头像，刷新确认；创建宠物并核对出生/领养日期、kg、绝育状态与备注。
3. 添加喂食和体重记录，核对宠物关联、类型筛选、倒序和刷新持久化；补测其余四类记录。
4. 为异常记录测试图片格式、大小和九张上限；出现部分保存时验证不会重复文字记录。
5. 选择该宠物向 AI 询问近期记录相关的问题，确认等待状态、即时回答、正确上下文、免责声明及历史。
6. 保留同请求编号模拟未知结果后检查，不重复扣次；明确失败后新提问计次。并发限额使用受控服务端测试，不仅看前端计数。
7. 记录三条真实体重，核对周/月/年及原始数值表；少于三条显示空状态。
8. A 开通社区昵称，发带标签和图片的临时动态；B 浏览、点赞、评论、收藏、关注，并刷新验证。
9. 核对获赞只统计已发布动态，取消/删除/下架后回读变化；举报与收藏保持私有。
10. 验证账号双向绑定并用另一标识和原密码登录，用户 ID 与原数据不变；退出后受保护页面要求重新登录。

## 权限与异常场景

以 B 尝试读取、更新、删除 A 的私人资料、宠物、记录、AI 历史及未公开社区内容，预期被拒绝或返回不可见结果。直接 API/RPC 还需验证 owner 伪造、外宠物关联、非法图片路径、越权审核与重复互动，不只测按钮是否隐藏。

模型 429、503、无效结构、截断与超时已有受控传输测试；这不是上游真实故障演练。清楚标注注入测试与真实服务调用。短信需分别核对 Hook 验签、供应商受理、真实收件和 Auth 验证；每个阶段不能互相冒充。

界面检查桌面与手机布局，覆盖加载、空状态、错误、重试、确认、重复提交和快速切换筛选；预览尺寸不能当作真实机型。签名图片访问权限和旧链接剩余有效时间应按实际服务核对，不因删除界面卡片就认为链接即时失效。

## 当前证据与待验边界

截至本册依据的记录，150 项本地自动测试、26 组全面开发云端业务、39 项首轮响应式检查，以及后续协议/获赞 3 组云端和 15 项布局检查已分别记录。注释提交 9259ee8 的 GitHub Actions 通过；这些数字属于不同执行批次，不能相加写成新一次全量验收。

用户反馈手机号/邮箱注册验证和各浏览器运行正常，记为用户验收，未补造设备版本或到达率。GAP-01 协议、GAP-02 获赞和 GAP-03 Pages 版本已补齐。真人独立接手演练尚未执行；自然会话到期按用户决定移出本轮范围。

原项目文档明确写有 4G 首屏不超过两秒、接口平均不超过 500 毫秒和 48 小时稳定性观察。现有读取采样与浏览器预览不能证明这些指标已验收，本轮没有新增压测或长期观察。当前后端为开发环境，Free 套餐的泄露密码检测提醒仍保留。

## 交付判定与记录模板

通过结论应同时满足：对应场景执行有证据、异常及权限断言通过、临时数据清理结果明确、构建与发布版本一致、剩余边界得到记录。仅本地构建成功不能当作上线完成；仅网站可打开不能证明跨用户隔离。

每次记录代码提交、日期/时区、环境、账号角色、场景编号、实际步骤、预期/实际、证据位置和清理结果。问题单补充复现路径、影响范围及修复后回归，避免把历史通过记录改成当前结果。

以下附录按项目 TEST-MATRIX 原表整理，包含 101 个场景。每行场景不等于一个 Vitest 测试；原始报告保留在 docs/FULL-TEST-REPORT.md、GAP-FIXES.md 和 TEST-RESULTS.md。附录结果是已记录状态，本册制作没有重新执行这些业务步骤。
